# test/

This folder is a development archive, not part of the production pipeline. It holds the intermediate scripts, exploratory analysis, and output files produced while building the signal and strategy used in `engine.py`. Nothing here is imported or executed by the final project — it's kept for reference and reproducibility of the discovery process.

## Contents

**Discovery scripts**
- `discovery_v3.py`, `signal_discovery_v2.py` — statistical scans that tested additional tickers and multi-condition signal gates alongside the primary lead-lag relationship. Kept because they document what was tried and ruled out (e.g. a second ticker filter that added no predictive power at usable trade frequency).
- `top_signal_summary.txt`, `discovery_v3/` — raw output of the discovery scans (Spearman IC rankings, hit rates, correlation tables) that the final signal parameters were chosen from.
- `conditional_rules.csv`, `deterministic_scan.csv`, `lead_lag_results.csv`, `spread_analysis.csv`, `two_ticker_interactions.csv`, `volume_state_results.csv` — supporting data tables generated by the discovery scripts above.

**Engine iterations**
- `engine.py`, `engine_candidate_v2.py`, `backtest_engine.py`, `strategy_engine.py` — earlier and alternate versions of the backtesting engine, superseded by the single `engine.py` at the repository root. `strategy_engine.py` in particular documents a bug found and fixed during development (a signal that turned over too often and lost money to fees).

**Validation**
- `validate_and_score.py`, `moccm_grader_modified.py` — earlier copies used while building the validation logic now in the root `validate_and_score.py`.

**Result snapshots**
- `submissions/`, `submission_v2/` — earlier runs of the output CSVs, kept as a history of results across iterations. The current results are in the root `submissions/` folder.

**Reference material**
- Hackathon briefing documents (`.docx`, `.pdf`) and an earlier draft `README.md` from when this project was built for a competition.

**Compiled artifacts**
- `__pycache__/` — Numba JIT compilation cache, safe to delete, regenerated automatically on first run.

## Why it's kept

These files trace the actual research process — what signals were tested, what was rejected and why, and what broke along the way. They're not needed to run the project (see the root `README.md`), but they're useful for anyone who wants to see how the final approach was arrived at.
